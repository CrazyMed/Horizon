## [长鑫科技筹备科创板 IPO，一季度营收同比暴增 719%](https://api3.cls.cn/share/article/2373399?os=android&amp;sv=8.7.8&amp;app=cailianpress) ⭐️ 8.0/10

## [付费项目利用 ML 研究计划欺骗高中生引发学术诚信担忧](https://www.reddit.com/r/MachineLearning/comments/1tfh2s9/program_misleading_high_school_students_into/) ⭐️ 7.0/10

一位 Reddit 用户揭露了 Algoverse AI Research，这是一个向高中生营销 ML 论文发表机会的付费项目。审查该项目的论文后发现明显错误——包括相反实验条件报告相同数值结果、拼写错误和章节错位——但这些论文都通过了 NeurIPS workshop 审核。 这揭示了掠夺性学术项目利用学生对研究资历的渴望进行剥削，并引发了对 NeurIPS workshop 同行评审是否能充分捕获明显错误的质疑。高中生及其家庭可能在获得误导性资历时遭受经济损失，而这些资历可能并不具备他们预期的价值。 Kevin Zhu 隶属于 Algoverse AI Research，在 OpenReview 上显示 158 篇论文和 468 位合著者。一篇被审查的论文对两个相反的实验条件（'污名负面'与'污名正面'）报告了相同结果，该项目声称 289 名学生被 NeurIPS 2025 录取。Workshop 论文通常比主会议论文接受更轻度的同行评审。

reddit · r/MachineLearning · Marisu_BG · 05月17日 06:08

**背景**: OpenReview 是一个开放同行评审平台，被包括 NeurIPS 在内的 ML 会议广泛使用。NeurIPS workshop 是主会议期间举办的卫星活动，出版标准较低——其目标是吸引新想法，即使实验结果尚不成熟。一些组织利用这一点，向希望增强大学申请竞争力的学生营销研究'项目'，形成了一个以学术抱负为目标的掠夺性产业。

## [OpenClaw 开发者单月消耗 130 万美元 OpenAI API 费用](https://www.tomshardware.com/tech-industry/artificial-intelligence/openclaw-creator-burns-through-1-3-million-in-openai-api-tokens-in-a-single-month) ⭐️ 7.0/10

OpenClaw 开发者 Peter Steinberger 披露，其团队在 30 天内消耗了价值 130 万美元的 OpenAI API Token，处理了 6030 亿个 Token 和 760 万次请求，由约 100 个 Codex 代理完成。计费主要源于 Codex 的"快速模式"定价，团队在无限预算条件下测试 AI 驱动的自主代码审查和安全扫描。 130 万美元的账单使用了 Codex 的快速模式，在标准定价下会自动降至约 30 万美元。值得注意的是，API 日志中提及的 GPT-5.5 模型版本日期为 2026 年 4 月 23 日，该模型尚未由 OpenAI 正式宣布。由于 Steinberger 在 OpenAI 工作，相关成本由公司全额承担，作为压力测试实验的一部分。

telegram · zaihuapd · 05月17日 13:38

**背景**: OpenAI Codex 是一个大型语言模型，经过源代码微调后可将自然语言提示转换为可执行代码，支持多种编程语言。该模型是 GitHub Copilot 的基础，现已作为独立编码代理使用。OpenAI 的 API 定价模式按消耗的 Token 收费，"快速模式"以更高费率提供优先访问。用于代码审查的 AI 代理是自主系统，无需人工干预即可分析代码变更、识别问题并强制执行编码标准。

## [开发者观点：AI 无法加速流程，因为需求本身就不清晰](https://frederickvanbrabant.com/blog/2026-05-15-i-dont-think-ai-will-make-your-processes-go-faster/) ⭐️ 6.0/10

一位软件开发者在博客中提出，大型语言模型等 AI 工具实际上无法加速软件开发流程，因为需求定义不清、功能请求模糊一直是真正的瓶颈——而 AI 反而迫使团队更清晰地表述这些问题，而不是绕过它们。 这一观点挑战了 AI 将显著提升开发者生产力的主流叙事。如果瓶颈不在编码而在需求清晰度，企业可能需要重新思考 AI 采用策略，将更多投入放在需求工程上，而不是期望 AI 神奇地解决效率问题。 文章指出，开发团队经常收到模糊的需求，比如"获取数据并呈现给用户"，但没有指定数据来源、存储方式或返回格式。虽然部分评论者持不同意见，认为 AI 可以加速构思、文档编写和部署，但作者认为 AI 无法绕过对精确问题定义的根本需求。

hackernews · TheEdonian · 05月17日 12:13 · [社区讨论](https://news.ycombinator.com/item?id=48168221)

**背景**: 需求工程是软件开发中的关键阶段，涉及收集、分析和明确系统应实现的功能。研究表明，需求不清晰或不完整是项目失败和成本超支的主要原因。自 2023 年以来，大型语言模型(LLMs)已被广泛应用于代码生成和开发辅助，但它们对上游需求阶段的影响仍然有限，因为它们只能根据收到的输入进行处理。

## [英国政府数字服务在 NHS 关闭仓库后发布"默认开放"指南](https://simonwillison.net/2026/May/17/gds-weighs-in/#atom-everything) ⭐️ 6.0/10

英国政府数字服务（GDS）于 2026 年 5 月 14 日发布了题为"公共部门中的人工智能、开源代码与漏洞风险"的指南，建议公共部门代码应"默认开放"而非在收到漏洞披露后转为私有。该指南似乎是对 NHS 在收到 Anthropic 项目 Glasswing 的漏洞报告后关闭开源仓库这一争议决定的直接回应。 这代表了 GDS 在通常是内部公务员事务中罕见的公开干预，表明政府中央数字机构不同意 NHS 处理开源安全的方式。该指南可能为公共部门组织如何平衡透明度与安全问题树立先例，并可能影响英国政府机构的技术政策走向。 GDS 明确指出，"将所有代码设为私有会增加额外的交付和政策成本，并可能减少代码重用和审查"，建议关闭应"谨慎且有意识地使用"。评论员将 NHS 的决定描述为"考虑不周"，Terence Eden 将 GDS 的指南解读为重大升级——将其比作公务员文化中"被邀请参加没有饼干的会议"这一表达，暗示这是非同寻常的公开分歧。

rss · Simon Willison · 05月17日 15:59

**背景**: 项目 Glasswing 是 Anthropic 的协调漏洞披露计划，使用其 Claude Mythos Preview 人工智能模型识别关键基础设施中的安全问题，并与负责基本服务的组织合作。英国政府数字服务是英国科学、创新技术部门内负责转型在线公共服务和制定政府数字标准的核心机构。在英国公务员文化中，被邀请参加"没有饼干的会议"是一个众所周知的表达，意味着特别严厉或令人不快的讨论。
